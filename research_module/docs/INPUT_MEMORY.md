# ResearchSpace 约定与长期开发备忘录（2026-10-18）

> 此文件是项目中可供所有 Agent 读取的**显式、版本化的项目记忆**。它不是 ChatGPT 账户的长期记忆写入，也不包含任何真实用户的私密画像。

## 产品定位与范围
- 名称：ResearchSpace（本科生科研空间），主题为「连接」；链接本科生、科研方向、导师/团队、公开科研机会、学生经验、科研联系。
- 面向本科生，第一阶段聚焦清华大学的导师与渠道（尤其 SRT），项目机会可扩展至中国其他高校与海外高校**公开发布且可核实参与资格**的本科生研究项目。
- 用户端闭环：**本地账号创建/切换 → 六步兴趣画像 → 导师研究/项目发现 → 查看可核查依据和推荐理由 → GitHub 公共交流 → 个性化中英邮件草稿/手工发送**。
- 四个插件 ID 固定：`faculty`（导师信息与匹配）、`opportunities`（科研项目）、`community`（公共交流）、`outreach`（套瓷邮件）。主程序负责账号、画像、路由、模块自动发现、统一接口/本地存储/AI 代理/设置。
- 用户要求可协同：主程序和四 Agent 独立开发，通过冻结的 `src/sdk/contracts.ts` v1.0.0 对接；`src/modules/<id>/module.tsx` default export `ResearchModule`；交付可直接解压的 ZIP，自动识别。

## 个人画像能提供什么
**输入（轻量、可选、不确定友好）：**
1. 本科年级与院系（不强制披露学校身份）。
2. 目的：尝试科研、寻找课题组、SRT、暑研、海外科研、升学准备（多选）。
3. 研究兴趣：宽领域、多选主题、自由关键词；允许尚无明确方向。
4. 基础技能、课程项目和实践证据（Python/数学/实验/文献/数据/设计等）；不从 GPA 推断价值。
5. 偏好工作类型（论文/代码/理论/实验/数据/调研）及指导方式（结构化/自主/未确定）。
6. 可开始时间及每周可投入时长，使用语言（中/英）。

**输出（服务于用户行动，而非贴标签）：**
- 用户可编辑的科研兴趣/能力/时间画像概览；跟踪兴趣变化。
- 导师适配的**可解释匹配参考分**：兴趣交集、已有技能证据、投入时间与项目要求、团队指导信息是否充分；同时列出未知项和建议准备事项。
- 方向探索路径与适合试做的小任务；推荐研究主题、团队、具体项目及其所需技能，提供来源与查询日期。
- 机会资格/招募状态双重过滤，避免把“方向相关”等同于“目前可加入”。
- 为个性化邮件生成提供真实、由学生确认的技能与经历、实际读过的资料、所希望的参与方式。
- 形成个人候选清单、待核查问题和联系准备记录；跨模块保持一致。

**不提供／不应推断：**
- 不强制输入真实姓名、学号、GPA 或敏感个人数据；本地账户不是清华身份认证。
- 不依据匹配分伪造录取率/套瓷成功率；无经同意收集的历史结果、可识别的样本分母与校准评估时，显示“无法可靠估计”。
- 不把学术合作关系误当师生指导关系，不推断导师私生活、人格/录取倾向。

## 信息来源与状态原则
- 导师：官方机构主页、课题组成员公开名单、公开论文元数据、正规公开演讲与视频；分别显示来源、访问日期。视频只提供可信链接或有权限取得的文稿摘要。
- 机会：清华 SRT 等通知、国内外高校公开项目网页、官方报名链接；**资格 eligibility** 与 **招募状态 status** 是两个独立字段；“往年曾招募”≠“现在开放”。仅在有近期可核查公告时显示“已确认开放”。
- 数据收集适配器可替换；首版无联网接口时用**醒目标注的虚构演示数据**与明确空状态，禁止把演示数据当真实机会。
- 公开评价重视第一手经历、时间与项目背景；个人体验非权威事实，社区要有行为守则、纠错、举报入口。

## 对“小Git书”的继承与约束
- 曾设计 README 作为主要内容，Issues 评论，保留原始仓库链接；偏好轻后端、利用 GitHub 原生能力。
- 此项目公开交流用 GitHub Discussions + giscus 优先；GitHub 登录负责真实社区身份，本地账号与 Github 身份独立。
- “小Git书”里曾考虑私有仓库 + Issue comments 私聊，最多 10 好友并限制消息长度；**本项目第一版暂不做私聊**，此机制只作为后续可选设计，不要混入社区模块。

## 技术与并行工作协议
- 主程序 React 19 + TypeScript + Vite + React Router + Tailwind CSS；本地用户/画像/草稿用 IndexedDB；模块通过 HostApi 访问账户隔离的存储，跨模块导师与项目用 HostCatalog。
- `src/sdk/contracts.ts` 为不兼容修改的冻结协议源，所有开发者都阅读 `docs/模块集成协议.md`。
- AI 服务经统一 HostApi，不在客户端硬编码模型 API key；如发送画像到远程 AI，需要明确逐次许可；邮件默认生成草稿，不自动发送。
- Agent 提交 ZIP 结构应直接是 `src/modules/<id>/...`，不得包含整个主程序/自己的 node_modules。
- 进入真实数据阶段先小范围试点：2~3 个领域、20~30 位公开导师资料、10~20 个项目线索、3 个方向 Space，并验证状态准确性。

## 开发优先级
P0：可运行的主程序（本地账户、首次画像、个性首页、设置与数据导入导出、插件发现/缺省页、统一 API）。
P1：四个可独立安装的功能插件，按 `docs/模块集成协议.md` 交付。
P2：数据采集/清华项目与导师来源核实、导师/项目联动、社区实际配置与主持维护。
P3：个人申请进度、科研试做任务、愿意答疑的学长学姐、讲座/公开组会、团队资料认领与更新。

## 作为 Agent 的操作要求
任何 Agent 开工先读 `MEMORY.md`, `docs/产品规划.md`, `docs/模块集成协议.md`, `src/sdk/contracts.ts`；不要用新一份不兼容接口覆盖约定。新决定须写进版本控制并更新本文件。
