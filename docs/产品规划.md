# ResearchSpace 本科生科研空间｜产品与开发规划

## 1. 目标与定位

- 主题：「连接」——连接本科生、导师、科研项目和同学的经验。
- 第一目标人群：清华大学希望开始科研、选择项目或寻找导师的本科生；项目库可扩展国内其他高校和海外高校**公开发布、且注明本科生是否具备申请资格**的机会。
- 核心闭环：本地注册 → 轻量画像 → 浏览 / 筛选导师与项目 → 查看证据与推荐理由 → 在公共空间提问 → 生成并人工确认联系邮件 → 记录下一步（草稿、本地待办）。
- 首版不依赖后端账户系统，不要求任何学校统一身份认证；需如实标注本地账户不等于真实身份认证。

## 2. 用户流程

首次打开：
1. 首页介绍、浏览示例、开始按钮；点击开始在当前浏览器创建本地档案（昵称 + 头像颜色或图标即可；生成随机 UUID）。
2. 创建档案后必须完成**精简的 6 步选择题**，每步 1~2 个问题，允许“尚不确定”，确保没有研究经验的本科生也可以完成。
3. 自动生成一个可编辑的「我的科研画像」概览，列出想探索的方向、目标、技能与证据、每周可投入时间、希望获得的指导方式；展示“这些内容用于推荐，不代表学术能力评价”。
4. 进入个性化首页，四个功能卡：导师调查、科研项目、公共 Space、套瓷邮件。
5. 用户浏览导师或项目时可以收藏，跨模块导航到邮件助手并携带 `facultyId` / `opportunityId`。
6. 用户可随时编辑画像，四个模块立即接收更新后的 profile；全部本地数据可导出 JSON、导入或删除。

### 首次画像问卷（建议题库）

| 步骤 | 问题 | 选项与逻辑 |
|---|---|---|
| 1 | 你现在处于本科第几年？ | 大一/大二/大三/大四/其他/暂不确定 |
| 2 | 这次来想解决什么问题？（多选） | 探索方向/参加 SRT/进入实验室/暑研/海外科研/研究生准备 |
| 3 | 哪些主题让你好奇？（多选） | AI 与计算/物理与数学/生命医学/电子与工程/人文社科/经管/设计与交叉/还没想好；可填关键词 |
| 4 | 目前有哪些可用技能或经历？（多选） | 编程/数学与理论/实验与仪器/数据分析/文献阅读/设计调研/课程项目/暂无经历；可选补充作品 |
| 5 | 你倾向怎样参与科研？（多选） | 读论文/写代码/推导/做实验/处理数据/实地调研/不知道；希望的指导方式：结构化/自主/不确定 |
| 6 | 什么时间参与比较合适？ | 现在/本学期/下学期/暑假/不确定；每周时间 0/3/5/10/15/20+ 小时 |

不能强制填写 GPA、真实姓名、手机号、政治倾向、病史等敏感信息；不给用户贴「不适合科研」等人格判断标签。初次六步完成后允许修改所有选项。

## 3. 四大功能的 MVP 定义

### A. 导师调查 `faculty`
- 教师搜索、方向筛选、导师详情、公开团队成员与身份、代表性论文、官方主页、公开报告和视频索引。
- 个人画像匹配：输出 **兴趣相关度 / 能力准备度 / 指导信息充分度** 等解释，列出匹配与不足的具体证据。可以展示“匹配参考分”，但不得展示伪造的“套瓷成功率”。
- 招募信息分开标为：已证实开放、历史曾招募、明确关闭、未知。
- 公开信息必须有证据来源；团队成员只能使用主动公开的学术/职业信息；不得推断私下师生关系或以论文合作关系冒充指导关系。
- 详情页按钮：「收藏」「查找相关项目」「围绕该导师提问」「准备联系邮件」。

### B. 科研项目 `opportunities`
- 合并展示清华 SRT、校内本科生科研助理/科研实践，以及国内外高校公开发布的本科生研究机会。
- 栏目与过滤：学校/国家/学科/项目种类/资格/状态/截至日期。
- 每条必须区分“有公开项目公告”与“用户符合申请资格”。非清华的公开项目不应默认清华学生可以申请。
- 重要状态：开放已确认、即将开放、已关闭、未知。展示 `statusVerifiedAt` 与原始公告；只有具备时间与来源依据，才能写「正在招募」。
- 详情页展示：研究目标、实际任务、导师/指导者、时长、投入时间、前置技能、申请方式、来源与最新核实日期。
- 允许从项目一键跳到导师页、联系邮件页、讨论区。

### C. 公共 Space `community`
- 三种讨论：科研方向入门提问、导师/项目经验、科研机会讨论；底层用公开 GitHub Discussions。
- 第一版可用本地演示帖子呈现排版，但要醒目标注「演示内容」；真实发表/回复跳 GitHub Discussions，导师/项目页面可用 `@giscus/react` 直接嵌入对应讨论区。
- 实际帖子作者显示 GitHub 身份，不能冒充本地账号名；不提供无依据匿名「评价导师」排名。
- 支持引用来源、提交问题模板、举报说明、使用规则、信息纠错入口；评论不能被当成官方事实。
- 如果未配置真实公开仓库，显示「社区尚未连接」与配置说明；其他板块保持可用。

### D. 套瓷邮件 `outreach`
- 根据用户画像 + 公开导师与项目信息 + 用户选定的联系目的生成中文或英文邮件，默认不发送；输出主题、称呼、正文、署名、可附材料建议。
- 两种工作模式：无 AI 时由确定性的本地模板生成完整可编辑草稿；AI Provider 配置后生成更自然的版本。
- 必须明确区分「只看过介绍」「看过摘要」「认真读过」「复现/项目相关经历」，禁止 AI 凭空写读过论文或做过实验。
- 生成前展示将发送给外部模型的数据，用户明确同意后才调用远程 AI；提供复制、下载 .txt、本地保存、重写、切换语种。
- 可记录联系状态（准备中/已发送/收到回复/已结束），这是**本地用户自己标记**，不声称邮件被真实发送；无 Gmail、SMTP 依赖。

## 4. 网站结构

```
/                        公共落地页
/welcome                 本地创建 / 选择账户
/onboarding              六步科研画像
/app                     个性化科研首页
/app/profile             个人画像与本地隐私/导入导出
/app/faculty             导师检索
/app/faculty/:facultyId  导师详情
/app/opportunities       项目检索
/app/opportunities/:id   项目详情
/app/community           公共 Space
/app/community/:topic    固定主题讨论 / GitHub 跳转
/app/outreach            套瓷助手
/app/settings            设置及 AI/社区连接状态
```

主程序负责站点统一路由、侧边栏、全局搜索框、推荐位容器、收藏入口、面包屑、加载/空/错误状态。

## 5. 严格限定的开发技术栈

- React 19 + TypeScript；Vite 作为打包工具；React Router；Tailwind CSS；lucide-react。
- `idb` 仅供主程序管理 IndexedDB；所有模块通过注入的 `api.storage` 读写用户信息。
- `zod` 做入站记录校验：网络抓取结果、导入 JSON、演示数据载入都要验证，不依靠 TypeScript 静态类型假设外部数据永远正确。
- 公共组件以 `src/ui/` 为准，尽量使用标准 HTML 和 Tailwind；功能模块不得引入独立路由器、React 副本、状态管理大框架或数据库。
- `@giscus/react` 由主程序预装，公共空间模块可直接使用。
- 使用 `npm` 和 `package-lock.json` 作为唯一锁文件；根级 `scripts` 至少包括 `dev`, `build`, `typecheck`, `test`, `check`。
- Node 版本见主程序 `.nvmrc`（建议 Node 22 LTS），依赖以主程序 `package-lock.json` 锁定。

## 6. 同步与信息来源的原则

- 第一版：模块内 `fixtures/*.json` 有足量**明确标记为虚构**的联调数据，页面无需外网也能工作。
- 第二阶段：增加官方信息的 `SourceAdapter`，通过明确允许的 API 或独立采集程序生成经过人工抽查的静态数据快照；不要让浏览器直接抓取可能跨域或要求校内登录的页面。
- 第三阶段：向经过核实的教师/项目联系人开放认领更新入口；过期机会失效处理；人工审核社区提供的新机会。
- `Source` 必须保留标题、URL、来源类型、发布时间（如有）、采集时间。AI 生成的摘要不是来源。
- 视频只展示可核实的官网/发布方链接；有合法可得的字幕或文稿时才生成带引用摘要。不要从演讲风格推断导师人格、录取倾向或团队内部关系。

## 7. 研发阶段与并行分工

**阶段 0（先锁协议）**：把 `sdk/contracts.ts` 定为 v1.0.0；建立宿主空壳、模拟账号、路由、示例目录、模块自动发现与测试。主程序 Agent 对接口负责，未经所有人认可不可破坏性修改。

**阶段 1（主程序与四 Agent 并行）**：
- 主程序：登陆/切换本地档案、问卷、首页、设置、跨模块能力、单元与集成测试。
- 导师 Agent：搜索/详情、数据适配器、画像匹配、媒体索引、导师数据提供者。
- 项目 Agent：统一项目类型/筛选/状态/详情、项目数据提供者。
- 社区 Agent：问答页、话题结构、GitHub 跳转、giscus、未配置降级。
- 邮件 Agent：多语言草稿、审计每一条个人与导师陈述、AI/模板双模式。

**阶段 2（模块集成）**：主程序合并模块 ZIP，仅在自动发现器与宿主侧做兼容性修复；修复任何协议不符的功能包由功能 Agent 完成。补齐跨功能从导师 → 机会/社区/邮件，从项目 → 导师/邮件/社区。

**阶段 3（试点数据与实测）**：选取 2～3 个方向，采集已允许公开的导师与项目资料；核实招募状态；邀请学生验证检索、推荐、问答与邮件草稿。评价任务完成率、信息正确率、功能能否切换、用户是否知道下一步该做什么。

## 8. 与已有产品拉开距离

相比单纯“导师主页聚合”或“自动发邮件工具”，首版重点做：
1. 科研背景与**本科生具体能做什么**同时呈现。
2. 「研究相关」「本科生可参与」「当期名额已确认」三个标签**互不混淆**。
3. 方向、导师和项目页面均有可追溯来源、能追问的问题与可延伸的交流。
4. 所有推荐建议都与画像中真实的技能、时间和兴趣挂钩，不声称能计算真实录取成功概率。
