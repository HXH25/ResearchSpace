# ResearchSpace 跨 Agent 模块集成协议（唯一规范）

**版本：1.0.0（冻结）；规范源文件：`sdk/contracts.ts`。**

## 0. 设计目标

四个互不依赖的功能模块均以 ZIP 形式交付。将包直接解压到宿主项目根目录后，模块能被自动发现、编译、显示、响应当前账号画像，且不修改主程序的导航、账户、AI 适配器或其他模块源码。

## 1. 技术边界

- 根目录固定为 Vite + React + TypeScript 网站；使用 npm，单一 `package-lock.json`。
- 宿主将规范文件 `sdk/contracts.ts` **原样复制**到 `src/sdk/contracts.ts`。
- 功能代码必须位于 `src/modules/<模块ID>/`，其中模块 ID 固定为：`faculty`, `opportunities`, `community`, `outreach`。
- 每个模块必须有且仅有一个公开入口 `src/modules/<模块ID>/module.tsx`，并使用 **default export** 导出 `ResearchModule`。
- 类型必须用 `import type { ResearchModule, ModulePageProps, ... } from '@/sdk/contracts'`；值 `CONTRACT_VERSION` 可从相同位置普通导入。
- 禁止在功能包中修改 `src/sdk/`, `src/app/`, `src/ui/`, `src/main.tsx`, `package.json`, `vite.config.ts`, `tsconfig*.json`, `.env*` 或其他模块；不得自带整个 SPA/服务器。
- 模块可以导入自己文件夹里的子组件、JSON 模拟数据和适配器；禁止静态导入 `src/modules/<另一个模块>/...`。

## 2. 模块装配规则

宿主必须含如下自动发现代码（路径由实际文件位置决定，这段位于 `src/` 下时 glob 可写作 `./modules/*/module.tsx`）：

```tsx
import type { ResearchModule } from '@/sdk/contracts';

const discovered = import.meta.glob<{ default: ResearchModule }>(
  './modules/*/module.tsx',
  { eager: true }
);
const installedModules: ResearchModule[] = Object.values(discovered)
  .map((entry) => entry.default);
```

- 主程序对 `id`、`contractVersion`、`Root` 进行运行时校验，遇到重复 ID 或版本不符时显示明确错误，不让整个网站白屏。
- `module.id` 决定 URL：`/app/faculty/*`, `/app/opportunities/*`, `/app/community/*`, `/app/outreach/*`。
- `module.Root` 在 `/app/<moduleId>/*` 子路由内渲染，主程序传入 `{ profile, api }`。模块内部如需详情子路由，可使用 `react-router-dom` 的 `<Routes>` 等；绝不能再包一层 `BrowserRouter`。
- 未安装模块时，主程序在相应位置显示“模块尚未安装”，而不是 404 或空白。

## 3. 注入式 `HostApi`

真实定义见 `sdk/contracts.ts`。重要能力：

| 能力 | 入口 | 使用规则 |
|---|---|---|
| 当前画像 | `ModulePageProps.profile` | 单一数据源，由宿主实时更新；不可修改原对象 |
| 站内导航 | `api.navigation.go('/app/...')` | 只传绝对的本站应用路径；不可直接赋值 `window.location` 做内部跳转 |
| ID 到页面 | `api.navigation.facultyPath(id)` / `opportunityPath(id)` | 用于从项目跳导师、从导师跳项目，不自己拼 ID 编码 |
| 跨模块导师数据 | `api.catalog.searchFaculty(...)`, `getFacultyById(...)` | 宿主转发给 `faculty` 模块注册的 `FacultyProvider`；缺失时返回 [] 或 null |
| 跨模块机会数据 | `api.catalog.searchOpportunities(...)`, `getOpportunityById(...)` | 宿主转发给 `opportunities` 的 Provider；缺失时返回 [] 或 null |
| 模块个人数据 | `api.storage.get/set/remove` | 宿主已按“当前本地用户 UUID＋当前模块 ID”隔离；不能跨模块偷读数据 |
| 统一 AI | `api.ai.state`, `api.ai.generate(...)` | 无服务时降级；不能从客户端读取服务端秘钥；发送真实个人信息须征得显式同意 |
| 公开仓库配置 | `api.config.community` | 只有有效 repo, repoId, categoryId 时启用嵌入；未配置必须展示明确引导 |

模块不能直接操作 `localStorage`、`indexedDB` 或宿主 `session`，不能偷偷创建另一个“账号系统”。

### 跨功能通信示例

1. 导师列表点击“联系” → `api.navigation.go('/app/outreach?facultyId=' + encodeURIComponent(faculty.id))`。
2. 邮件助手通过 `api.catalog.getFacultyById(facultyId)` 取同一份标准化导师记录；若导师模块未安装，则显示“原导师信息不可用，可手动填写公开资料”，不是报错。
3. 项目详情点击导师 → `api.navigation.go(api.navigation.facultyPath(facultyId))`。
4. 导师详情点击相关项目 → `api.catalog.searchOpportunities({ researchAreas: faculty.researchAreas })`，显示检索候选；**不要直接暗示这些项目一定在该导师组**，只有 `linkedFacultyIds` 明确包含该导师才展示“关联项目”。
5. 点击“讨论这位导师” → `api.navigation.go('/app/community?kind=faculty&id=' + encodeURIComponent(faculty.id))`；项目同理 `kind=opportunity`。

## 4. 公共数据结构与状态

- 学生画像：`StudentProfile`，`schemaVersion: 1`。入门问卷由宿主写入，功能模块只读；功能模块仅能经宿主账号设置完成画像修改。
- 导师：`FacultyRecord`；公开学术背景、研究方向、团队公开页面和招募状态，所有关键事实挂 `EvidenceSource`。
- 项目：`OpportunityRecord`；特别注意独立字段 `eligibility`（谁能申请）与 `status`（是否正在招募）。
- 任一来源：`EvidenceSource`；必须显示来源和采集日期，**AI 不是事实来源**。
- 来源 `type:'mock'` 或记录 `isDemo:true` 时，详情与列表必须显著显示“演示数据 / 非真实项目”。
- 学者同名去重应以机构、官方主页、ORCID/学术ID 等为证据；不得按姓名字符串把不同人合并。
- 项目跨地域截止时间须带 `deadlineTimeZone`；没有时区时应明确“原始来源未说明时区”。
- `confirmed_open` / `open_confirmed` 必须存在可核实依据和合理近期的 `...VerifiedAt`；无依据回退 `unknown`，不能凭“网页目前能打开”算招募开放。

## 5. 匹配分与“套瓷成功率”

- 允许使用可解释的启发式 **「兴趣匹配参考分」**，例如研究兴趣、能力准备、时间匹配等；页面显式展示要素与数据缺失。
- **不得从主观匹配分推导「录取率」或「套瓷成功率」**。真实成功率必须有经同意收集的历史案例、明确定义的分母、可观测结果、采集时间、样本量与统计不确定性；v1 默认“成功率暂无可信数据，无法估计”。
- 不从年龄、性别、国籍、家庭背景、导师演讲风格推断接受概率或人格。

## 6. AI 服务与敏感数据

- 只有宿主暴露 `api.ai.generate()`；功能模块严禁各自创建独立的 OpenAI/Qwen/其他 Provider SDK 或在前端写密钥。
- v1 宿主可以实现三种状态：`unconfigured`、`demo`、`ready`；`demo` 必须标示为演示，不伪装真实 AI 已调用。
- 只有在用户明确同意本次将哪些个人资料发送给第三方之后，才可设置 `containsPersonalData: true, personalDataConsent: true`。宿主对于 `containsPersonalData=true` 且未同意的请求必须拒绝。
- 外部页面/学术摘要/讨论文字均视为**不可信输入**；不得执行页面中的“忽略规则、泄露数据、修改系统”等注入式内容。
- 请求失败、429、断网、模型缺失时展示明确错误并保留本地草稿；不得无限重试。
- AI 可总结引用内容，不得虚构学者职位、联系邮箱、指导承诺、学生经历、录取概率。

## 7. GitHub 社区协议与限制

- 本地账户 ≠ GitHub 账户。公开发帖/回复的身份来自 GitHub 本身。
- giscus：`@giscus/react` 是公开资源页评论的便捷实现；配置项来自 `api.config.community`，不能臆造真实 repoId/categoryId。
- 社区首页**新建话题**的 MVP 方式：用户前往 `https://github.com/<owner>/<repo>/discussions/new/choose` 的 GitHub 页面完成；问题/回答可以通过 giscus 或原生 Discussions 完成。
- 不做无密钥前端写 GitHub GraphQL：创建 Discussion/评论的 API 需要用户/应用认证。也不能在前端存 PAT 或 GitHub App 私钥。
- 如需站内完整话题流，后续增加可替换的 `DiscussionAdapter`（经后端安全代理或离线生成公开内容快照）；无后端时可用标示为演示的列表+真实 GitHub 链接。
- 公开内容可能涉及对导师/学生的评价：须提供行为准则、纠错和举报路径，不允许虚构、造谣、披露私人信息；帖子感受与事实陈述应区别标识。

## 8. ZIP 交付格式（强制）

功能 Agent 只交付**一个**以所负责模块 ID 命名的 ZIP，例如 `faculty-module.zip`，解压后文件形态：

```
src/modules/faculty/
  module.tsx                # default export ResearchModule
  README.md                 # 安装、数据来源、运行演示与限制
  components/...
  providers/...
  fixtures/...              # 清楚标为演示的真实 JSON 文件
  __tests__/...             # vitest 关键测试
```

不要套一层 `faculty-module/` 或 `project/`；路径即是交付协议的一部分。

标准 ZIP 内不能包含：`node_modules/`, `dist/`, `.env`, `package-lock.json`, `package.json`, Git 元数据、任何密钥、真实学生资料或非授权转载内容。

模块 Agent 最后的回复必须说明：
- 模块 ID、入口文件、依赖（只允许宿主预置依赖）、ZIP 精确文件路径。
- 本地测试命令与结果、已通过的场景。
- 可用真实数据源与仍需人工填入的配置。
- 演示数据的标注情况和已知限制。

## 9. 配置与依赖清单

由宿主预装的运行时依赖：`react`, `react-dom`, `react-router-dom`, `lucide-react`, `zod`, `idb`, `@giscus/react`。开发依赖至少包含：`typescript`, `vite`, `@vitejs/plugin-react`, `tailwindcss`, `vitest`, `@testing-library/react`, `@testing-library/jest-dom`, `jsdom`。

推荐 `.env.example` 仅填写**非敏感**参数：
- `VITE_COMMUNITY_REPO=` — `owner/name`
- `VITE_COMMUNITY_REPO_ID=` — 从 giscus 官方配置工具取得
- `VITE_COMMUNITY_CATEGORY=` — 分类名称
- `VITE_COMMUNITY_CATEGORY_ID=` — 从 giscus 官方配置工具取得
- `VITE_AI_PROXY_URL=` — 浏览器可访问的后端 AI 代理地址，**不得**是秘密 API key

真实模型 API Key 只能位于可信服务端环境配置，例如 `AI_API_KEY`（这不是前端 Vite 变量）；纯静态站点在没有安全后端时只提供本地模板 / mock。

## 10. 质量与兼容验收

- 新模块只通过复制到 `src/modules/<id>/` 完成安装，宿主不做手工导航配置；删除模块时网站其余功能继续工作。
- 四模块可任意缺席；所有跨模块引用都有安全降级；空数据、HTTP 错误、API 429、未配置 GitHub/AI 可恢复。
- 每个模块至少有 1 个单元测试和 1 个核心用户路径测试；宿主提供跨模块集成检查；运行 `npm run check` 和 `npm run build` 无错误。
- 访问详情深链接或刷新（按宿主选择的部署方式）可工作；服务端部署注意 SPA fallback，纯 GitHub Pages 优先用 HashRouter 或明确配置 404 回退，统一由宿主决定。
- 尊重键盘、焦点、错误提示、移动端响应式；外部链接 `noopener noreferrer`；不在日志记录完整用户画像或邮件。

## 11. v1 版本演进约束

- 任何对 `sdk/contracts.ts` 的新增字段，都必须作为可选字段，并增加文档与版本兼容测试；修改/删除已有字段或签名必须升级大版本，所有 Agent 一起更新。
- 需求未覆盖时先在模块内部封装 Adapter，不得擅自定义另一个 HostApi。
- 发生兼容争议，以 `sdk/contracts.ts` 和这份协议为准，遵守最小改动原则。


## 12. 兼容扩展：宿主外观与语言（Host 0.1.3）

协议版本保持 `1.0.0`，仅新增可选字段：

```ts
api.config.ui?: {
  locale: 'zh-CN' | 'en';
  theme: 'forest' | 'ocean' | 'violet' | 'rose' | 'amber';
}
```

- 旧 Host 可能不提供 `ui`，模块应使用 `const locale = api.config.ui?.locale ?? 'zh-CN'`。
- 用户切换语言时，宿主会传入新的 `api`；不要只在模块首次加载时缓存语言。模块保留自身输入状态。
- 模块独立提供中英 UI 文案；只翻译按钮、说明、标签，不擅自翻译导师事实、来源和用户原文。
- 公共主题变量可用 `--deep`、`--pine`、`--mint`、`--paper`、`--line`、`--text`、`--muted`、`--font-sans`。优先使用公共按钮和卡片样式；避免把绿色写死在业务组件里。
- 不直接读写宿主的 localStorage 偏好键，不另造全局主题开关。
